# Документація API: Notification Service (ArcaBank)

Цей мікросервіс відповідає за доставку сповіщень користувачам у реальному часі.
Він не має стандартних REST ендпойнтів. Взаємодія з клієнтами відбувається через протокол WebSocket (STOMP), а внутрішня комунікація з іншими мікросервісами — через брокер повідомлень Kafka.

---

## 1. WebSocket Інтеграція (Для Фронтенду / Мобільних додатків)
Використовується для отримання push-сповіщень у реальному часі. Підтримується SockJS.

### 1.1 Підключення (Handshake)
**Ендпойнт:** `WS /ws-notifications` (або `HTTP /ws-notifications` при використанні SockJS)
**Бізнес-логіка:** Встановлює постійне WebSocket-з'єднання між клієнтом та сервером. Дозволені запити з будь-яких доменів (CORS `*`).

### 1.2 Підписка на сповіщення (Subscribe)
Щоб клієнт почав отримувати сповіщення, після встановлення з'єднання він повинен підписатися на свій персональний STOMP-топік.
**Топік для підписки:** `/topic/user.{userId}`
*(де `{userId}` — це UUID поточного авторизованого користувача).*

### 1.3 Формат повідомлення (Message Payload)
Коли система генерує нове сповіщення (наприклад, про надходження коштів), клієнт отримає у свій топік повідомлення у форматі JSON.

**Приклад отриманого JSON (Подія STOMP MESSAGE):**
```json
{
  "id": "e3b0c442-989b-464c-8650-1234567890ab", // Унікальний ідентифікатор сповіщення
  "notificationType": "TRANSFER_INCOME", // Тип сповіщення (див. довідник нижче)
  "actionType": "NAVIGATE", // Тип дії при кліці (див. довідник нижче)
  "userId": "123e4567-e89b-12d3-a456-426614174000", // UUID власника сповіщення
  "userEmail": "user@email.com", // Email користувача
  "title": "💸 Надходження коштів!", // Заголовок сповіщення
  "text": "На ваш рахунок зараховано 1500.00 UAH.", // Текст сповіщення
  "endpoint": "/api/v1/transfers/history" // Маршрут для переходу (залежить від actionType)
}
