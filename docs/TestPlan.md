Test Plan: Система онлайн-банкінгу «ArcaBank»
1. Вступ (Introduction)

Мета: Перевірка працездатності, безпеки та надійності вебсистеми «ArcaBank» для управління рахунками, здійснення P2P переказів та створення спільних накопичувальних скриньок (Vaults).


Об’єкт тестування: 

Модуль ідентифікації (реєстрація, авторизація, JWT-токени).

Модуль фінансового ядра (P2P перекази, обчислення балансу).

Модуль спільного накопичення (Створення скриньок / Escrow).

2. Стратегія тестування (Testing Strategy)

Рівні тестування: 


Unit Testing: Перевірка алгоритмів обчислення залишків на рахунках та валідації сум.


Integration Testing: Перевірка взаємодії Frontend ↔ API (Backend) ↔ PostgreSQL (БД).


System Testing (E2E): Проходження повних користувацьких сценаріїв (від реєстрації до успішного P2P переказу).


Види тестування: 


Functional Testing: Перевірка того, чи списуються кошти з одного рахунку та зараховуються на інший.

Security Testing: Перевірка захищеності ендпоінтів. Спроби доступу до чужих рахунків без валідного токена або з підробленими правами.


Boundary Value Analysis: Перевірка граничних значень (спроби переказу від'ємних сум, нульових сум або сум, що перевищують баланс).


API Testing: Перевірка JSON контрактів, статус-кодів та обробки помилок через REST API.

3. Ресурси та інструменти (Tools)

API тестування: Postman / Swagger UI.


Unit тестування (Backend): JUnit 5 + Mockito (для Spring Boot).


Bug Tracking: Jira (або Notion-дошка зі статусом Bug).


Середовище: Локальні сервери розробників, браузер Google Chrome, контейнери Docker (PostgreSQL).

4. Критерії «Прийняття» (Acceptance & Exit Criteria)

Критерії початку (Entry Criteria): Код розгорнуто на локальному або тестовому сервері, база даних ініціалізована міграціями (Liquibase), затверджені Test Cases.


Критерії завершення (Exit Criteria): 

Виконано 100% запланованих позитивних та негативних Test Cases.

Виправлено 100% Critical та High багів (наприклад, вразливості безпеки або неправильні розрахунки балансу).

Усі ключові Use Cases (Happy Path) проходять без жодної помилки або затримки.

5. План виконання (Schedule)

Етап 1: Тестування логіки бази даних, валідацій та API-ендпоінтів через Postman.


Етап 2: Тестування інтерфейсу користувача (Frontend), валідації форм та обробки клієнтських помилок.


Етап 3: Фінальне регресійне наскрізне тестування перед демонстрацією MVP.

6. Очікувані результати (Deliverables)

Bug Reports: Картки в таск-трекері (Jira) з детальним описом знайдених дефектів.


Підсумковий звіт: Звіт про перевірку готовності MVP із зазначенням пройдених тест-кейсів та можливих некритичних обмежень системи.
